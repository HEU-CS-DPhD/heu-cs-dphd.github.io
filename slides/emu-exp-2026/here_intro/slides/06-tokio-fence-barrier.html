◈ 核心亮点三：Rust + Tokio —— 内存栅栏与无畏并发保障

严格遵循 VirtIO 规范内存模型：原子操作、内存栅栏与 DrainBarrier 优雅退出机制
❖ 异步 Worker 任务执行与内存屏障virtio_block.rs
async fn run_task(&mut self, task: VirtIOBlockAsyncTask) {
    // 1. 同步 Guest 在 QueueNotify 前发布的所有写入
    std::sync::atomic::fence(Ordering::Acquire);

    match task {
        VirtIOBlockAsyncTask::Read(t) => self.read(t).await,
        VirtIOBlockAsyncTask::Write(t) => self.write(t).await,
        VirtIOBlockAsyncTask::Flush(c) => {
            let status = if self.file.sync_data().await.is_ok() {
                VirtIOBlkReqStatus::Ok
            } else { VirtIOBlkReqStatus::IoErr };
            c.complete(status, 1);
        }
        VirtIOBlockAsyncTask::DrainBarrier(ack) => { let _ = ack.send(()); }
    }
}
完成时 c.complete 原子置位 status 并触发 PLIC 中断。
❖ 无畏并发设计与工程保障
  • 跨线程数据安全与内存栅栏： Worker 在消费任务前通过 atomic::fence(Ordering::Acquire) 强制同步 Guest 发布的数据；发布 Used 环时执行写状态与释放屏障。
  • 安全排空屏障 (DrainBarrier)： 当 Guest OS 驱动发起设备重置（Device Reset）时，模拟器注入 DrainBarrier 同步阻塞排空所有飞行中的异步 I/O 任务。
  • 优雅停机与刷盘保障： 模拟器退出时通过 watch::channel 广播取消信号，确保调用 File::sync_data().await 刷盘落盘，彻底杜绝镜像文件损坏。
❖ 编译期无数据竞争保证
Rust 的 Send + 'static 静态约束保证传递给 Tokio 线程的任务数据所有权明确，杜绝悬垂指针与并发写写竞争。
