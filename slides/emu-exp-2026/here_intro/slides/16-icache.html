◈ 模块二：CPU 前端译码 —— 译码指令缓存 (iCache)

为高频循环与系统调用热点打造的硬件级直接映射缓存 (Direct-Mapped Decoded Cache)
❖ 为什么需要 iCache 仿真？性能飞跃引擎
在传统解释型模拟器中，指令译码（位移、字段提取、掩码匹配、符号拓展）占据高达 40%~60% 的 CPU 运算时间。
HERE 译码缓存实现：
通过 DirectCache<DecodeInstr, 8192>，直接将 PC 映射到预解析好的 DecodeInstr，热点指令重复执行几乎等同于查表！
❖ 缓存表项定义 (DecodeInstr)
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct DecodeInstr {
    pub instr: RiscvInstr, // 指令枚举标识符
    pub info: RVInstrInfo,  // 预解码的操作数 (rd, rs1, rs2, imm)
    pub len: WordType,      // 指令字节长度 (2 或 4)
}
❖ 缓存失效与自修改代码 (Zifencei)纪元失效机制
当动态链接或 JIT 写回内存并发起 fence.i 时，iCache 必须安全失效：
icache_epoch += 1 (O(1) 逻辑清空机制)
每个缓存行记录写入时的 epoch。失效时只需递增全局 icache_epoch，旧缓存行自动判定为 Miss 重新加载，免除 8192 表项内存写开销。
